# ReelRoom outcomes

- [x] **Rooms and attendance** — Create and join rooms via invite link or room code. Handle at least 10 concurrent users per room. Reliably handle late joins, reconnections, and concurrent actions.
  - Evidence: the 10-client loopback harness exercises concurrent control delivery, reconnection, late-join snapshots, action buffering, and host-session ownership.
- [ ] **Synchronized playback, YouTube, and local-network performance** — Sync play, pause, and seek across all participants. Automatically detect and correct playback drift. Playback control propagation must be ≤ 250 ms at p95 on a local network. Playback drift must be ≤ 500 ms after correction. Add a way to use the supplied YouTube URL `https://youtu.be/lo4bA4p3MBQ?si=kIuKwVv10g5ma5xR`. Preload a movie's verified official/public-domain full-film URL when one exists.
  - Evidence and remaining boundary: direct video and official IFrame Player support are implemented; the supplied short URL is validated and canonicalized. Every loaded title remains host-playable through the source input. Verify each saved film source before marking catalog work complete; separate-device LAN latency, browser embed permission/autoplay, and physical media drift remain unmeasured.
- [x] **Shared movie discovery** — Provide movie recommendations with categories, filters, and fuzzy search.
  - Evidence: category, industry, mood, runtime, and genre filters plus typo-tolerant search operate on database-loaded records.
- [x] **Database-backed top-movie catalog and Start Here shelf** — Add a database which will contain some top movies. Differentiate the movies based on Bollywood and Hollywood as well as based on genre. After adding them to the database, add them in the Start Here section with appropriate images and data of the movie. Add up to a total of 30 movies. Prioritize verified official/public-domain full-film URLs where available.
  - Evidence: the managed database and catalog API now return exactly 30 featured titles, split 15 Bollywood / 15 Hollywood; all 30 appear in Start Here with local posters and visible industry/genre badges. Twenty-two new posters were added as proportion-preserved WebP assets and visually reviewed. Fifteen supported official-source or U.S.-public-domain video URLs have source/rights notes; direct media endpoints returned byte-range responses, and YouTube embed/region uncertainty is disclosed. The other 15 titles remain selectable but correctly require a host-provided video link.
- [x] **Room collaboration and host lifecycle** — Provide emoji reactions, live chat, shared playlists, group polls, and host transfer.
  - Evidence: the shared room snapshot/events and persistent store cover all five collaboration behaviors; playback authority is checked server-side.
- [x] **Latency evidence and failure handling** — Document latency measurements, test conditions, and failure handling; report the actual measurement context and limitations without representing unmeasured conditions as verified.
  - Evidence: [docs/performance-and-failures.md](docs/performance-and-failures.md) records measured loopback results, thresholds, conditions, limitations, and recovery behavior; the report will note YouTube-specific embedding and source failure behavior.
- [x] **Anonymous display-name default** — Instead of keeping the default username as `Alex`, use `anonymous10298391`-style names, with a randomly generated number after `anonymous`; keep the generated name stable for that browser unless the user saves a different name.
  - Evidence: a browser-persisted `anonymous` plus eight random digits is generated on first use, old uncustomized `Alex` values migrate, and explicitly saved names are preserved. Identity tests cover generation, migration, stability, and a visitor deliberately saving `Alex`.
